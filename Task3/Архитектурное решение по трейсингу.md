# Архитектурное решение по трейсингу

## Мотивация 

### Сбои в межсервисном взаимодействии :

   - **Проблема:** Заказы зависают, а сообщения теряются при передаче между сервисами

   - **Последствие:** Нарушается целостность данных и непрерывность бизнес-процессов

### Недоступность данных для операторов :

   - **Проблема:** Операторы не видят заказы, поступающие через Shop API

   - **Последствие:** Невозможность обработки заказов вручную, задержки в обслуживании клиентов.

### Отсутствие мониторинга бэкенд-систем :

   - **Проблема:** Яндекс.Метрика не получает данные от бэкенд-компонентов (RabbitMQ, MES, CRM).

   - **Последствие:** Потеря прозрачности работы ключевых систем, невозможность своевременно выявлять сбои.

## Предлагаемое решение

В качестве решения проблемы потери заказов и длительного устранения неполадок предлагается внедрение трейсинга (tracing), обеспечивающего сквозное отслеживание запросов между сервисами.

На каждом этапе жизненного цикла заказа участвующие сервисы вносят записи о своих операциях. Указанные записи впоследствии агрегируются в рамках общего идентификатора traceId, формируя целостную картину прохождения заказа через все компоненты системы.

Будет использован Jaeger.

### Внедрение трейсинга даёт следующие результаты :

- **Сокращение времени восстановления (MTTR)** — период устранения инцидентов уменьшится

- **Снижение доли потерянных заказов** — количество транзакций, не дошедших до обработки, сведётся к минимуму

- **Ускорение обработки жалоб клиентов** — время разбора и ответа на обращения сократилось

## Компромиссы

Трейсинг должен быть выборочным для экономии ресурсов. Так, из трейсинга исключаются:

- внешнее API

- внутренняя работа MES

## Аспекты безопасности

### 1. Защита данных
- Исключить передачу персональных данных в трейсах
- Шифрование хранилища и каналов передачи
- Ограничение доступа к хранилищу

### 2. Управление доступом (IAM)
- Аутентификация и авторизация в веб-интерфейсе Jaeger
- Отсутствие публичного доступа к UI и Collector'у
- Ролевая модель: чтение / поддержка (саппорт) / администратор
- Доступ к инфраструктуре только через изолированные namespace
- RBAC (Role-Based Access Control) на уровне кластера

### 3. Сетевая безопасность
- Прием трейсов только от доверенных namespace (сетевые политики)
- Collector и UI доступны исключительно внутри кластера

### 4. Мониторинг и аудит
- Ведение аудита доступа к системе и данным
